## Root cause of 0 covered pixels (verified)

- The software mesh processor (`Chronon3d/src/backends/software/processors/software_mesh_processor.cpp`) projects with `Camera::projection_matrix` (right-handed `glm::perspective`, visible when view z < 0).
- The 2.5D projection contract (`include/chronon3d/math/camera_projection_contract.hpp`) is forward-positive (visible when view z > 0), with `x = f*x/z` and screen y flipped.
- The mesh path also receives a hard-coded `Camera{}` from `src/runtime/render_pipeline.cpp` (fov 60, position z=-1000), not the scene's Camera2_5D. Its focal length (about 55 px at depth 1000) differs from the 2.5D zoom focal (1000 px), so a 40 px mesh at z=0 would be about 1 px even after the sign is fixed.
- Measured (64x64 probe): 2D flat mesh at z=0 gives 0 px. A convention-only fix (`perspectiveLH` plus sign-flipped clip/depth) gives 3 px, which confirms the sign mismatch. The remaining gap is focal length.
- Existing canary `test_render_plan_inline_mesh.cpp` (z=-1500, enable_3d) is visible only under the old convention; it would need re-placement after the fix.
- Next step: pass the scene's Camera2_5D (or its focal) into the mesh path from the Render Plan pipeline, and move the canary and `test_mesh_roughness_map.cpp` to forward-positive coordinates.
